# ГРАФ РАЗБЛОКИРОВОК — ТЗ №08 (полная система жанра)

Пишется до кода (N-10). Узлы — то, что игрок открывает за валюту забега
(«трофеи», иконка 🏆, копится по битвам, не сбрасывается между битвами
кампании в рамках одной сессии — сейв вне объёма фазы, см. `ВЫДАЧА`/фаза 10).
Рёбра — зависимости (нельзя купить, пока не куплен родитель). Разблокировка
меняет ГЛАГОЛ («теперь можно купить юнита B в бою» — раньше нельзя было),
апгрейд меняет ЧИСЛО (доход, HP, урон) — оба вида узлов в одном графе, но
только у разблокировок глагол/число различаются по сути.

## Архитектурная развилка (см. BLOCKERS.md)

`balance.units[type]` — ОДНА запись на тип, используется ОБЕИМИ сторонами
(движок не различает игрока/врага при чтении hp/damage/speed). Апгрейд
«урон типа A», применённый напрямую к `balance.units.A.damage`, усилил бы
и вражеских A тоже — свёл бы себя на нет. Решение: `engine.js` получает
необязательный `balance.player_unit_overrides[type]` — аддитивные бонусы
(`damage_bonus`, `hp_bonus`), применяются ТОЛЬКО при `isPlayer===true` в
`spawnUnit`. Без overrides (пусто/нет ключа) поведение побитово прежнее.

## Узлы

| id | Название игроку | Тип | Эффект | Стоимость (трофеи) | Зависит от |
|---|---|---|---|---|---|
| `unlock_B` | Открыть стрелка (B) | разблокировка | карта B доступна в бою | `unlocks.unlock_B.cost` | — (доступен с начала) |
| `unlock_C` | Открыть щит (C) | разблокировка | карта C доступна в бою | `unlocks.unlock_C.cost` | `unlock_B` |
| `income_N` | Доход еды (ур. N) | апгрейд, до `upgrades.income.max_level` | `player.production_rate += step` | `upgrades.income.cost_base × N` | — |
| `base_hp_N` | HP базы (ур. N) | апгрейд, до `upgrades.base_hp.max_level` | `player.base_hp += step` | `upgrades.base_hp.cost_base × N` | — |
| `damage_A_N` | Урон бойца A (ур. N) | апгрейд | `player_unit_overrides.A.damage_bonus += step` | `upgrades.damage_A.cost_base × N` | — (A доступен с начала) |
| `damage_B_N` | Урон стрелка B (ур. N) | апгрейд | `player_unit_overrides.B.damage_bonus += step` | `upgrades.damage_B.cost_base × N` | `unlock_B` |
| `damage_C_N` | Урон щита C (ур. N) | апгрейд | `player_unit_overrides.C.damage_bonus += step` | `upgrades.damage_C.cost_base × N` | `unlock_C` |

Числа уровней/шагов/стоимостей — в `balance.json.campaign.upgrades` и
`.unlocks`, ни одного числа в коде (жёсткое требование CLAUDE.md).

## Рёбра (зависимости)

```
unlock_B ──▶ unlock_C ──▶ damage_C_*
   │
   └────────▶ damage_B_*

(income_*, base_hp_*, damage_A_* — без родителя, доступны с первой битвы)
```

## Почему так

- Первые три битвы игрок обязан выигрывать (закон 1) — граф не гейтит
  ничего критического за деньги, которых у новичка ещё нет: со стартовым A
  и без единого апгрейда битвы 1-3 должны быть выигрышны (проверяется
  ботом-кампанией, порог 1 раздела «Порог» ТЗ №08).
- `unlock_C` зависит от `unlock_B`, а не наоборот — щит без стрелков за
  спиной бессмысленен (вывод фазы 06/07: роль щита доказана именно в паре
  со стрелками).
- Урон типа отдельным узлом на тип (не один общий «урон») — интерпретация
  ROADMAP.md («урон типов», множественное число), даёт содержательный выбор
  между экономикой (income) и боевой мощью, а не одну кнопку «сделать
  сильнее».
