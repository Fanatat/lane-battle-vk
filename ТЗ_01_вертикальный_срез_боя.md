# ТЗ №01 — Вертикальный срез боя (прототип «до»)

**Рабочее имя:** Lane Battle (в интерфейс не выводить, имя не финальное)
**Папка:** указывается основателем, папка НОВАЯ и ПУСТАЯ
**Площадка:** никакая. Прототип открывается локально в браузере.
**Срок ориентировочно:** 1–2 дня.

## 0. Зачем это ТЗ

Дать основателю **60 секунд боя, в которые можно играть 20 минут подряд**, и получить
ответ на один вопрос: есть ли в этом жанре кайф без всякой меты.

Это прототип «ДО» — намеренно **без единого решения игрока в бою**. Следующим ТЗ на ту же
базу навешивается твист (превью волны врага + контр-типы), и мы сравниваем «до» и «после»
на живом билде, а не в рассуждениях.

Прототип не выбрасывается: если бой окажется живым, он становится ядром игры.

## 1. Границы — чего в этом ТЗ НЕТ

Ничего из списка не делать, даже если кажется, что «это же две строки»:

мета-экраны, апгрейды, эволюция, эпохи, карты, гача, магазин, задания, валюты кроме еды,
сохранение, платформенный SDK, реклама, аналитика, звук, финальный арт, локализация,
меню, туториал, экран загрузки, `platform.js`, `build.py`, версионирование билда.

Новая система входит только ВМЕСТО старой, а не поверх.

## 2. Правила сессии

- Папка новая: `git init`, первый коммит — пустой скелет, работа в ветке `prototype/battle`.
- Одна сессия = одна папка, из папки не выходить.
- Стек: vanilla JS + Canvas 2D. Без движков, без сборщиков, без рантайм-зависимостей.
- Файлы: `index.html`, `main.js`, `balance.json`, `dev.js` (панель отладки), `README.md`.
- Запуск: `python3 -m http.server` в папке, адрес печатается в конце отчёта.
- Отчёт по окончании — файлом `ВЫДАЧА/отчёты/ТЗ01_отчёт.md` (папка исключается из коммита
  через `.git/info/exclude`).
- Скриншот сцены в отчёт обязателен: «файл существует» приёмкой не является.

## 3. Сцена

- Один экран, без камеры, без скролла, без параллакса.
- Горизонтальная полоса боя через всю ширину. База игрока слева, база врага справа.
- Адаптив: работает и на 360×640 (портрет, телефон), и на 1280×720 (десктоп).
  На узком экране полоса короче, юниты НЕ уменьшаются.
- **Юнит не меньше 1/8 высоты экрана.** Это жёсткое требование, выведенное из отзывов
  лидера жанра (22 жалобы на неразличимые фигурки).
- Арт: цветные прямоугольники с буквой типа внутри. Никакой графики. Плейсхолдеры —
  это осознанное решение, а не отсутствие арта.
- Над каждым юнитом полоска HP. Над базами — полоска HP и число, **в одной размерности
  у обеих сторон**.

## 4. Правила боя

Три типа юнита, различаются только числами из `balance.json`:

| Тип | Роль | Ориентир |
|---|---|---|
| A | дешёвый, быстрый, слабый | спам |
| B | средний | база армии |
| C | дорогой, медленный, толстый | таран |

Автомат состояний юнита:

```
MOVE   — идёт к базе противника с постоянной скоростью
ATTACK — при контакте с ближайшим врагом по оси X останавливается и бьёт с интервалом attack_speed
SIEGE  — дойдя до базы противника, бьёт по базе
```

Цель — ближайший враг по X. Никакого выбора цели, никакого AoE, никакого промаха.

Юниты не проходят сквозь своих: очередь выстраивается, задний упирается в переднего.
Это важно для ощущения «волны» — без этого получится каша.

**Еда:** копится пассивно `food += production_rate * dt`, потолок `food_cap`.
Спавн юнита списывает его цену. Карточка юнита при нехватке — затемнена, но кликабельна,
клик даёт короткую отрицательную реакцию (тряска карточки), а не молчание.

**ИИ врага:** волновой спавн по таймеру с ростом плотности. Никакой экономики у врага нет —
он спавнит по расписанию из `balance.json`. Расписание — массив `{время, тип, количество}`.

**Конец боя:**
- HP базы врага = 0 → победа, попап «Победа», кнопка «Ещё раз».
- HP базы игрока = 0 → поражение, попап «Поражение», кнопка «Ещё раз».
- Попап показывает: длительность боя в секундах, сколько юнитов заспавнено, сколько убито.

## 5. Ощущение боя — это главная часть ТЗ

Числа можно подкрутить потом. Ощущение подкрутить потом нельзя, оно либо заложено, либо нет.

| Событие | Что происходит |
|---|---|
| Спавн юнита | squash 1.3 → 1.0 по вертикали за 120 мс |
| Попадание | цель вспыхивает белым на 60 мс, всплывает цифра урона (вверх 400 мс, затухая) |
| Смерть юнита | хит-стоп: симуляция замирает на 60 мс; тряска экрана 3 px, 120 мс |
| Удар по базе | тряска экрана 6 px, 150 мс; полоска HP базы дёргается |
| Разрушение базы | хит-стоп 200 мс, тряска 10 px, затем попап |

Хит-стоп реализуется глобальным множителем времени, а не `setTimeout` на отрисовку.

**Кнопка скорости ×1 / ×2 / ×3** — в углу экрана, доступна с первой секунды, без ограничений.
Переключается по кругу. Это прямой ответ на 27 жалоб «долго / медленно» у лидера жанра
и стоит копейки: множитель `dt`.

Цель по кадрам: 60 fps при 25 юнитах на поле на среднем Android. Пулинг объектов обязателен,
`new` в игровом цикле не вызывается.

## 6. Числа

**Ни одного числа в коде.** Всё в `balance.json`:
скорости, HP, урон, интервалы атак, цены юнитов, `production_rate`, `food_cap`,
HP обеих баз, расписание волн врага.

`dev.js` — панель отладки поверх сцены (скрывается клавишей `D`):
- ползунок на каждое число из `balance.json`, применение без перезагрузки страницы;
- кнопка «Рестарт боя»;
- живой вывод: время боя, спавнов, убийств, текущий DPS игрока, оставшаяся еда;
- кнопка «Скопировать текущий balance.json» — чтобы найденная настройка не потерялась.

Стартовые числа подбираются исполнителем так, чтобы **первый бой выигрывался** и длился
**100–120 секунд** на скорости ×1. Это отправная точка для тюнинга, а не истина.

## 7. Приёмка

Автотестами это не принимается. Принимает основатель руками, 20 минут игры.

Исполнитель обязан проверить перед сдачей:
- бой выигрывается и проигрывается, оба попапа появляются, «Ещё раз» работает;
- все кнопки кликаются мышью И пальцем (touch), проверено на 360×640 и 1280×720;
- ×1/×2/×3 переключается и реально меняет скорость симуляции;
- 25 юнитов на поле не роняют кадры;
- панель отладки скрыта по умолчанию.

**Вопросы, на которые основатель отвечает после игры** (вписать в отчёт как чек-лист):

1. После поражения хотелось нажать «Ещё раз» — или закрыть вкладку?
2. Был ли момент, когда ты понял, что побеждаешь, ДО того как победил?
3. Что ты делал, пока копилась еда? Смотрел на бой или ждал?
4. На какой скорости ты играл большую часть времени?
5. Что ты пытался сделать руками и не смог?

Вопрос 5 — самый ценный. Он покажет, какой твист игра просит сама.
